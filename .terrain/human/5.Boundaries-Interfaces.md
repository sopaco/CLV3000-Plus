# System Boundaries and Interfaces

This document describes how CLV3000 Plus interacts with the outside world. Despite being a desktop application, it has clear boundaries: persisted JSON settings, environment-variable overrides for agent tool paths, OS integration for disk/process/startup data, and the internal `clv-core` library API consumed by the GPUI shell. There is no REST API, no CLI for end users, and no network surface.

Understanding these boundaries matters when integrating the app into documentation workflows (Terrain), extending cleanup rules, or deploying on locked-down machines that require air-gapped operation.

| Property | Value |

On Windows, the binary links with `windows_subsystem = "windows"` to avoid a console flash on double-click (`main.rs:3`).

## Persisted Settings (`AppSettings`)

Settings are stored as JSON via `directories::ProjectDirs` at `com.clv3000.plus` config path — see `settings_path()` in `crates/clv-core/src/settings/mod.rs:48`.

| Field | Type | Default | Meaning |
|-------|------|---------|---------|
| `scan_paths` | `Vec<PathBuf>` | Home Projects/Documents/Desktop/etc. | Roots for `Scanner::scan_tree` |
| `expert_mode` | `bool` | `false` | Show Protected items and full technical paths |
| `soft_delete` | `bool` | `true` | Move to trash vs permanent delete |
| `soft_delete_days` | `u32` | `7` | Auto-purge trash entries older than N days |
| `include_agent_heuristics` | `bool` | `true` | Agent project + session discovery |
| `auto_scan_weekly` | `bool` | `false` | Weekly scan preference |
| `onboarding_done` | `bool` | `false` | Skip first-run onboarding page |
| `language` | `LanguagePreference` | system | zh / en / ja resolution |
| `theme` | `ThemePreference` | default | GPUI theme (cherry, aurora, neon, …) |

**Interpretation** — `scan_paths` is the primary tuning knob: it defines where project rules run. `expert_mode` shifts the UI from "plain language" to "full path + protected items." `soft_delete` is the safety default; turning it off is appropriate only when you trust bulk permanent deletion.

Example config location (macOS/Linux): `~/.config/clv3000/plus/settings.json`.

## Environment Variables

Agent session discovery respects overrides for non-standard install locations:

| Variable | Used in | Purpose |
|----------|---------|---------|
| `TRAE_DIR` | `agent_sessions.rs` | Trae CLI data root |
| `TRAEX_SESSIONS_DIR` | `agent_sessions.rs` | TraeX session storage |
| `OPENCODE_DIR` | `agent_sessions.rs` | OpenCode data directory |
| `CODEX_HOME` | `agent_sessions.rs` | Codex home resolution |
| `LOCALAPPDATA`, `APPDATA`, `TEMP` | `paths.rs:52` | Windows global rule path prefixes |
| `RUST_LOG` / tracing filter | `main.rs:109` | Debug logging (dev builds) |

Global cleanup rules use `$LOCALAPPDATA/`, `$APPDATA/`, `$TEMP/`, `$USERPROFILE/` prefixes in `resolve_global_path` (`crates/clv-core/src/paths.rs:52–71`).

## OS Integration Boundaries

| Capability | API | Source |
|------------|-----|--------|
| Primary disk usage | `primary_disk_usage()` | `crates/clv-platform/src/disk.rs:11` |
| Process list / kill | `ProcessEnumerator`, `kill_process` | `crates/clv-platform/src/process.rs` |
| Startup items | `list_startup_items`, `set_startup_enabled` | `crates/clv-platform/src/startup.rs` |
| Reveal in file manager | `open` crate | Used from views |
| App trash directory | `trash_dir()` | `crates/clv-core/src/paths.rs` |
| Protected path guard | `is_protected_system_path` | `crates/clv-core/src/paths.rs` |

**Read vs write** — Disk and process APIs are read-only (except `kill_process` and startup toggles). Cleanup writes only to user-selected scan item paths and the app trash dir.

## `clv-core` Public Library Surface

Exported from `crates/clv-core/src/lib.rs` for use by `clv-app`:

- **Scan** — `Scanner`, `ScanReport`, `ScanItem`, `ScanProgress`
- **Cleanup** — `CleanupExecutor`, `CleanupReport`
- **Agent** — `detect_agent_projects`
- **Settings** — `AppSettings`, `load_settings`, `save_settings`, `parse_scan_paths`
- **Types** — `TechStack`, `RiskLevel`, `CleanupCategory`, `CleanupBucket`
- **i18n types** — `RuleDescription`, `AgentReasonPart`, `Language`, `format_agent_reason`
- **Helpers** — `default_selected_item_ids`, `item_cleanup_bucket`

Domain types intentionally omit UI labels — resolution happens in `RuleDescription::text(lang)` or `crates/clv-app/src/i18n/labels.rs`.

## Developer Workflow: Adding Cleanup Rules

Documented in `AGENTS.md` at repository root:

1. Add `CleanupRule` in `project_rules.rs`, `global_rules.rs`, or `agent_sessions.rs`
2. Append translation in `scripts/rule-description-translations.json`
3. Run `python3 scripts/generate-rule-descriptions.py --patch`
4. Verify with `cargo test -p clv-core`

Do not edit `rule_description.rs` manually (AUTO-GENERATED).

## Integration Notes

- **Air-gapped environments** — Fully supported; no outbound network required.
- **CI / automation** — No headless CLI today; automation targets rule tests (`clv-core` unit tests) and Terrain knowledge in `.terrain/`.
- **Coding agents** — Load `AGENTS.md` and `.terrain/agent/context.md` before modifying scanner rules or i18n.
