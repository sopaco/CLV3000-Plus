# System Boundary Interfaces

This document describes every way users and integrators interact with CLV3000 Plus: the desktop shell, persisted settings, environment overrides, and the small public surface of `clv-core` if you embed scan logic elsewhere. There is no CLI, HTTP API, or plugin host—the product is intentionally a self-contained GUI binary.

## Desktop Application

**Binary:** `clv3000-plus` (from `crates/clv-app`, entry `main.rs`)

**Window:** 1280×720 centered (`main.rs:52`), custom title bar via `AppShell` (`shell.rs`)

**Navigation sidebar** (`app/mod.rs:203-241`):
| Icon | Page | Purpose |
|------|------|---------|
| Home | Dashboard | Health score, disk usage, scan trigger |
| Cleanup | Cleanup | Select and delete scan items |
| Agent | Agent | Agent/zombie projects |
| Startup | Startup | Boot items toggle |
| Process | Process | Memory/CPU processes |
| Settings | Settings | Mode, paths, theme, language |

**Keyboard:** Cmd/Ctrl+W closes the window (`main.rs:75-88`). macOS menu "Close Window" bound to the same action.

**First run:** If `onboarding_done` is false, `OnboardingView` collects Expert/Simple mode and initial scan paths (`app/mod.rs:35-40`).

## Configuration File

**Path:** Resolved by `directories::ProjectDirs::from("com", "clv3000", "plus")` → `config/settings.json` (`settings.rs:41-44`)

**Load/save:** `load_settings()` / `save_settings()` (`settings.rs:46-80`)

| Field | Type | Default | Interpretation |
|-------|------|---------|----------------|
| `scan_paths` | `Vec<PathBuf>` | `default_scan_paths()` | Directory roots walked by `Scanner`; typically Projects, Documents, Desktop, Developer |
| `expert_mode` | `bool` | `false` | When false, hides `RiskLevel::Protected` items and shows friendly paths instead of full paths in Cleanup view |
| `soft_delete` | `bool` | `true` | Move to app trash vs permanent delete—gives a undo window before `purge_old_trash` |
| `soft_delete_days` | `u32` | `7` | Age threshold for automatic trash purge |
| `include_agent_heuristics` | `bool` | `true` | Enables agent session path scan and `detect_agent_projects` post-pass |
| `auto_scan_weekly` | `bool` | `false` | Reserved; not wired to a scheduler in current code |
| `onboarding_done` | `bool` | `false` | Skips onboarding wizard when true |
| `language` | `LanguagePreference` | `system` | `system`, `zh`, `en`, `ja` |
| `theme` | `ThemePreference` | `defender` | `defender`, `blossom`, `neon`, `aurora` |

**Example settings.json:**

```json
{
  "scan_paths": [
    "/Users/me/Projects",
    "/Users/me/Documents"
  ],
  "expert_mode": false,
  "soft_delete": true,
  "soft_delete_days": 7,
  "include_agent_heuristics": true,
  "auto_scan_weekly": false,
  "onboarding_done": true,
  "language": "en",
  "theme": "defender"
}
```

**Scan path parsing:** `parse_scan_paths` accepts one path per line; supports `~/` expansion and Windows `%VAR%` expansion (`paths.rs:95-120`).

## Environment Variables

Agent tools store data in non-standard locations when users set home overrides. CLV3000 reads these when discovering session targets (`agent_sessions.rs`):

| Variable | Effect |
|----------|--------|
| `CODEX_HOME` | Overrides default `~/.codex` for Codex session paths |
| `CLAUDE_CONFIG_DIR` | Overrides Claude Code config root |
| `CODEBUDDY_HOME` | WorkBuddy / CodeBuddy data root |
| `TRAE_DIR` | Trae application data (parent of User dir) |
| `TRAEX_SESSIONS_DIR` | TraeX CLI session root |
| `OPENCODE_DIR` | OpenCode data directory |
| `LOCALAPPDATA`, `APPDATA`, `TEMP` | Used to resolve Windows global cache rules in `resolve_global_path` (`paths.rs:52-72`) |
| `XDG_DATA_HOME` | Linux-style OpenCode path on non-Windows |

## Trash Directory

Soft-deleted items are renamed to:

`ProjectDirs::data_local_dir()/trash/{timestamp}-{name}-{uuid}`

Defined in `trash_dir()` (`settings.rs:83-86`). Cleanup uses `fs::rename` (`cleanup.rs:99-112`).

## Public Library API (`clv-core`)

Exported from `crates/clv-core/src/lib.rs` for potential embedding:

| Export | Role |
|--------|------|
| `Scanner::new(settings).scan(callback)` | Run full scan with progress |
| `CleanupExecutor::new(settings).execute(items)` | Delete selected items |
| `detect_agent_projects(items, scan_paths)` | Build agent project list |
| `load_settings` / `save_settings` | Settings I/O |
| `item_cleanup_bucket` | UI bucket classification |
| `format_bytes` | Human size strings |

## Integration Notes

- **CI/automation:** No headless mode today; you would call `clv-core` APIs from a custom Rust binary.
- **Permissions:** macOS login-item disable requires Automation permission for System Events; Windows startup changes write HKCU StartupApproved (no admin for current user Run keys).
- **Security:** The app can delete large directory trees; always review selections—especially `RiskLevel::Caution` session folders labeled as non-recoverable in `agent_sessions.rs`.
