# System Boundary Interfaces

This document lists every way the outside world—or other code—interacts with CLV3000 Plus: the GUI entry point, persisted configuration, library exports, and platform APIs. There is no REST API or CLI subcommand surface; the primary interface is the desktop application plus JSON config files on disk.

## Application Binary

| Property | Value |
|----------|-------|
| Binary name | `clv3000-plus` |
| Package | `clv-app` (`crates/clv-app/Cargo.toml`) |
| Entry | `crates/clv-app/src/main.rs` |

On Windows, the binary links as a GUI subsystem so double-click launch does not open a console window (`main.rs` lines 1–3). Debug builds still attach tracing when run from a terminal (`main.rs` lines 108–115).

**Keyboard shortcuts**

| Key | Action | Definition |
|-----|--------|------------|
| Cmd/Ctrl+W | Close window | `CloseWindow` in `crates/clv-app/src/actions.rs`, bound in `main.rs:75-89` |
| macOS menu | Window → Close Window | `main.rs:100-106` |

## Configuration File (`settings.json`)

Settings are stored under the platform config directory resolved by `directories::ProjectDirs::from("com", "clv3000", "plus")` — see `crates/clv-core/src/settings/mod.rs:48-51`.

| Field | Type | Default | Meaning |
|-------|------|---------|---------|
| `scan_paths` | array of paths | `default_scan_paths()` | Directory roots for project walks (`paths.rs:8-48`) |
| `expert_mode` | bool | `false` | Show protected items and full technical detail |
| `soft_delete` | bool | `true` | Move to app trash instead of permanent delete |
| `soft_delete_days` | u32 | `7` | Days before `purge_old_trash` removes trash entries |
| `include_agent_heuristics` | bool | `true` | Enable agent session scan + project detection |
| `auto_scan_weekly` | bool | `false` | User preference (reserved for scheduled scans) |
| `onboarding_done` | bool | `false` | Whether first-run onboarding completed |
| `language` | enum | `system` | `system`, `zh`, `en`, `ja` (`locale.rs:21-27`) |
| `theme` | enum | `defender` | `defender`, `blossom`, `neon`, `aurora` (`locale.rs:7-17`) |

**Example** (illustrative):

```json
{
  "scan_paths": ["/Users/me/Developer", "/Users/me/projects"],
  "expert_mode": false,
  "soft_delete": true,
  "soft_delete_days": 7,
  "include_agent_heuristics": true,
  "auto_scan_weekly": false,
  "onboarding_done": true,
  "language": "en",
  "theme": "defender"
}
```

Load/save API: `load_settings()` / `save_settings()` in `settings/mod.rs:53-88`.

## Integration Suggestions

1. **Backup before migrate** — Copy `settings.json` and `cleanup_history.json` from the config dir when moving machines.
2. **CI / automation** — Depend on `clv-core` directly for headless scan reports; the GUI binary is not designed for scripted flags.
3. **Extend detection** — Add `CleanupRule` entries in `settings/project_rules.rs` or `global_rules.rs`; no scanner code change required for standard path rules.
4. **Soft-delete recovery** — Items remain in `data_local_dir()/trash` until retention purge; users can manually restore from there before `soft_delete_days` elapse.
