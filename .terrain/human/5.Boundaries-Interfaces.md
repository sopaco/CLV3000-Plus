# System Boundaries and Interfaces

This document covers every way CLV3000 Plus exposes itself to the outside world -- from the GUI layout that users interact with, to the configuration files that persist preferences, to the platform-specific APIs it calls under the hood.

---

## 1. GUI Interface (Primary)

CLV3000 Plus is a native desktop GUI application built with GPUI. All user interaction happens through the window interface -- there is no CLI, no REST API, and no headless mode.

### Window Layout

The application uses a standard desktop utility layout:

- **Top bar** (52px height): Application title "CLV3000 Plus", current page name, user mode badge (Simple/Expert), "One-Click Health Check" primary button
- **Left sidebar** (220px width): Navigation buttons for 6 pages (Dashboard, Cleanup, Agent, Startup, Process, Settings)
- **Main content area**: Active page content, scrollable
- **Status bar** (28px height): Scan status, last scan summary, or "Ready" message

### Pages

| Page | Nav Button | Description |
|------|-----------|-------------|
| Dashboard | `nav-home` | 4 stat cards (disk usage, reclaimable space, agent projects, startup items) + quick action buttons |
| Cleanup | `nav-clean` | Left filter panel (200px) + item list with checkboxes, batch actions, and detail expansion |
| Agent Projects | `nav-agent` | Agent project cards with name, size, risk, stacks, inactive days, and clean/open actions |
| Startup Items | `nav-startup` | Item list with name, kind, impact, description, and toggle switch |
| Process Manager | `nav-process` | Process table (top 50) with PID, name, CPU%, memory, category, sort buttons, kill button |
| Settings | `nav-settings` | Toggle switches for Expert Mode, Soft Delete, Agent Detection + scan directory display |
| Onboarding | (auto on first run) | 3-step wizard: Welcome, Mode Selection, Scan Path Preview |

### Key UI Actions

| Action | Location | Trigger | Effect |
|--------|----------|---------|--------|
| One-Click Health Check | Top bar + Dashboard | Button click | Starts async scan |
| Scan Agent Projects | Agent page | Button click | Starts scan |
| Clean Selected Items | Cleanup page | Button click | Opens confirmation dialog, then cleanup execution |
| Select All / Deselect All | Cleanup page toolbar | Button click | Batch selection toggle |
| Open Location | Item detail expansion | Button click | Opens path in system file manager |
| Toggle Startup Item | Startup page | Switch toggle | Enables/disables startup entry |
| Kill Process | Process row | Button click | Opens confirmation dialog, then SIGTERM |
| Toggle Expert Mode | Settings page | Switch toggle | Changes item visibility |
| Finish Onboarding | Wizard step 3 | Button click | Saves settings, starts first scan |

## 2. Configuration Structure

### AppSettings

**Location**: `{ProjectDirs}/com/clv3000/plus/config/settings.json`

This is the only persistent state in the application. The file is JSON, human-readable, and created automatically on first launch.

| Field | Type | Default | Purpose |
|-------|------|---------|---------|
| `scan_paths` | `Vec<PathBuf>` | ~/Projects, ~/projects, ~/Documents, ~/Desktop, ~/Developer, ~/dev, ~/code, ~/Code | Directories to scan for cleanable items |
| `expert_mode` | `bool` | `false` | Show full paths, more items, protected paths |
| `soft_delete` | `bool` | `true` | Move to trash instead of permanent delete |
| `soft_delete_days` | `u32` | `7` | Days before trash auto-purges |
| `include_agent_heuristics` | `bool` | `true` | Enable agent experiment project detection |
| `auto_scan_weekly` | `bool` | `false` | (Flag exists but not wired to scheduler) |
| `onboarding_done` | `bool` | `false` | Whether first-run wizard has completed |

### Example Configuration

```json
{
  "scan_paths": [
    "/Users/dev/Projects",
    "/Users/dev/Documents",
    "/Users/dev/Desktop"
  ],
  "expert_mode": false,
  "soft_delete": true,
  "soft_delete_days": 7,
  "include_agent_heuristics": true,
  "auto_scan_weekly": false,
  "onboarding_done": true
}
```

### Agent Detection Patterns

**Name patterns** (14): claude, cursor, codex, workbuddy, work-buddy, agent, generated, aider, copilot, windsurf, devin, bolt, v0, replit

**Marker files** (7): `.cursor`, `.claude`, `.aider`, `.copilot`, `.windsurf`, `AGENTS.md`, `CLAUDE.md`

### Protected System Paths

The following paths are never scanned or deleted:
- macOS: `/system`, `/library`, `/usr`, `/bin`, `/sbin`, `/etc`, `/private/var`, `/applications`
- Windows: `C:\Windows`, `C:\Program Files`, `C:\Program Files (x86)`, `C:\ProgramData`
- Exception: `/var/folders/` is NOT protected (contains useful temp data)

## 4. Library API (for programmatic use)

The `clv-core` crate can be used as a library for scripted cleanup:

```rust
use clv_core::{Scanner, CleanupExecutor, AppSettings};

// Configure and scan
let settings = AppSettings::default();
let report = Scanner::new(settings.clone()).scan(|progress| {
    println!("Scanning: {}", progress.phase);
});

// Review results
println!("Found {} items, {} agent projects",
    report.items.len(), report.agent_projects.len());
println!("Reclaimable: {}", report.total_reclaimable_human());

// Execute cleanup (select items first)
let executor = CleanupExecutor::new(settings);
let result = executor.execute(&selected_items);
println!("Freed: {}, Failed: {}", result.freed_bytes, result.failed.len());
```

## 5. Integration Suggestions

- **CI/CD**: Use `clv-core` as a Rust library dependency for automated workspace cleanup
- **Scripting**: Combine with `clv-core` library calls in build scripts to clean before fresh builds
- **Monitoring**: The `ScanReport` struct can be serialized to JSON for external analysis
- **Scheduled cleanup**: The `auto_scan_weekly` flag exists but needs a scheduler implementation (potential extension point)
