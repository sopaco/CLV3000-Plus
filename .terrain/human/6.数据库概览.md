# 数据库概览

CLV3000 Plus 是一款专注于本地文件系统清理的桌面工具，从设计之初就没有引入任何数据库。这并非偷懒或妥协，而是一个经过深思熟虑的架构决策。一款清理工具的核心职责是扫描、分类和删除文件，它本身产生的数据量极小——不过是一些用户偏好设置和最近几次扫描的记录。为不到一百 KB 的数据引入 SQLite 乃至嵌入式数据库引擎，无异于用推土机搬砖。无数据库设计让构建产物更小、依赖链更短、启动更快，同时也让数据对用户完全透明——打开 JSON 文件就能看到一切，不需要任何数据库客户端。

## 无数据库设计

项目采用"文件即数据库"的持久化策略，所有需要跨会话保留的数据都以 JSON 文件的形式写入操作系统的标准配置目录（macOS 上是 `~/Library/Application Support/`，Linux 上是 `~/.local/share/`，Windows 上是 `%APPDATA%`）。选择这种方案基于四个方面的考量。

其一，数据量极小。用户设置 `AppSettings` 序列化后通常不到 1 KB，单次扫描结果 `ScanReport` 也不过几十 KB。这个量级用 JSON 文本文件存储绰绰有余，没有任何性能瓶颈。其二，零外部依赖。不引入 SQLite 意味着最终二进制文件体积更小，编译依赖更少，交叉编译也更简单——对于一个以"轻量"为卖点的工具来说，这是必须坚守的底线。其三，人类可读可编辑。JSON 是纯文本格式，用户可以直接打开文件查看甚至手动修改，排查问题时一目了然，不需要额外的数据库查询工具。其四，原子写入已经足够。项目使用先写临时文件再 rename 的方式保证写入原子性，配合错误恢复机制，对于这种低频写入场景已经完全可靠，不需要数据库事务提供的更复杂的一致性保证。

## 持久化文件清单

| 文件 | 内容 | 写入时机 | 生命周期 |
|------|------|----------|----------|
| `settings.json` | `AppSettings` 序列化后的用户配置 | 用户修改设置时写入 | 永久保留，跟随应用安装 |
| `last_scan.json` | `ScanReport` 最近一次扫描的完整结果 | 每次扫描完成时覆盖写入 | 覆盖写，始终只保留最新一份 |
| `cleanup_history.json` | `CleanupHistory` 清理操作的历史记录 | 每次清理完成后追加写入 | 90 天滚动窗口，过期条目自动清除 |
| `trash/*` | 被软删除的原始文件 | 用户执行清理时移动至此目录 | 达到 `soft_delete_days` 天数后自动清理 |

这四类文件构成了 CLV3000 Plus 全部的持久化状态。它们各司其职：设置文件记录用户的长期偏好，扫描结果文件在两次扫描之间提供即时数据，清理历史文件用于审计和回溯，`trash` 目录则作为误删的安全网。这种分文件、按职责隔离的设计让每个数据域都保持独立，既不会因为某一个文件的损坏影响全局，也不会在数据增长时产生单一大文件的管理负担。对于当前的应用规模，这套方案简洁而可靠，未来即便需要扩展——比如增加多项目管理或导出功能——也只需要增加新的 JSON 文件，无需改变整体架构。
