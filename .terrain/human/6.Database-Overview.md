# Database Overview

---

## No Database Detected

CLV3000 Plus does not use a database. This is a deliberate architectural choice that fits the application's nature as a stateless file system scanner and cleaner.

The application doesn't need to persist scan history, user analytics, or relational data. The only persistent state is user preferences stored in a JSON configuration file at `{ProjectDirs}/com/clv3000/plus/config/settings.json`. This is a preferences file, not a database.

### Why No Database?

The app's core operation is ephemeral: scan the current file system state, present findings, and act on user selections. There is no historical tracking ("how much space did I free last month?"), no user accounts, and no relational data. A JSON config file is the right level of persistence for user preferences.

### Data Persistence Map

| Data | Storage | Format | Lifetime |
|------|---------|--------|----------|
| User settings | `{config_dir}/settings.json` | JSON | Permanent |
| Scan results | In-memory (`AppStore::last_report`) | Rust structs | App session only |
| Cleanup trash | `{data_dir}/trash/` directory | Files with timestamped names | 7 days (auto-purge) |
| Settings path | `{ProjectDirs::from("com", "clv3000", "plus")}` | OS standard | Permanent |

### Trash Directory Structure

When soft-delete is enabled (the default), cleaned files are moved to a trash directory with timestamped names:

```
{data_local_dir}/trash/
  20260820-143022-target-a1b2c3d4-e5f6-7890-abcd-ef1234567890
  20260820-143023-node_modules-b2c3d4e5-f6a7-8901-bcde-f12345678901
  20260820-143024-.next-c3d4e5f6-a7b8-9012-cdef-123456789012
```

The naming convention is: `{YYYYMMDD-HHMMSS}-{original_name}-{UUID}`. This prevents name collisions when cleaning multiple items with the same directory name from different projects, and makes trash entries easily browsable in a file manager.
