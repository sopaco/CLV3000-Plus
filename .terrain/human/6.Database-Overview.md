# Database Overview

CLV3000 Plus does not use a relational database, ORM, or SQL migration layer. That is a deliberate product choice: the app must install with zero infrastructure, run entirely on the user's machine, and persist only a small amount of preferences and cleanup history.

## How Data Is Stored Instead

Persistence is **file-based JSON** plus a **local trash directory**:

| Artifact | Location | Code reference |
|----------|----------|----------------|
| User settings | `ProjectDirs::config_dir()/settings.json` | `settings/mod.rs:48-61` |
| Cleanup history | `config_dir()/cleanup_history.json` | `cleanup.rs:113-116` |
| Soft-delete trash | `data_local_dir()/trash/` | `settings/mod.rs:90-93` |

`CleanupHistory` keeps records for 90 days (`cleanup.rs:75-78`) and exposes aggregates like `freed_in_days` for the dashboard.

## Why No Database

| Approach chosen | Alternative not used | Reason |
|-----------------|----------------------|--------|
| JSON files | SQLite | Simpler deployment; tiny data volume |
| In-memory scan reports | Persistent scan DB | Reports are session-oriented; rescan is cheap |
| OS filesystem for trash | DB-backed undo log | Users can browse trash folder directly |

## Statistics Summary

| Type | Count |
|------|-------|
| SQL tables | 0 |
| Views | 0 |
| Stored procedures | 0 |
| JSON persistence files | 2 (+ trash folder) |

If a future version needed historical scan comparison across months, SQLite would be a natural addition—but the current codebase has no hooks for that yet.
